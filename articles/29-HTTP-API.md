# 第29篇：HTTP API —— 给你的软路由装一个方向盘

## 一

一个长时间运行的服务必须提供一种方式让你知道它在干什么。不能是黑盒子。wifi2socks 大多数时间安静地跑在后台——没有 GUI、没有桌面图标——但当你需要知道"现在有多少设备连着？""流量走了多少代理？""这个 IP 是哪个国家的？"——你需要一个查询入口。

这个入口是 HTTP API。

## 二

`SimpleHttpServer` 是从零开始写的 HTTP 服务器，约 300 行。不处理完整 HTTP/1.1——分块编码、管道化、WebSocket 都不支持——只处理最基本的请求-响应模式。

设计决策：不引入第三方 HTTP 库。如果用了 cpp-httplib 或 libmicrohttpd，依赖链会变长且 Windows 上的编译更痛苦。一个够用的 HTTP 解析器只需要识别请求行和基本头部——200 行 C++ 够了。

## 三

API 设计原则：够用就好。`GET /api/stats`——实时流量、速率、连接数。`GET /api/rules/list`——当前规则。`POST /api/rules/update`——热更新规则（调用 `RuleManager::reload()`，原子替换，新连接立即生效）。`GET /api/proxy/check`——代理连通性测试。`GET /api/geoip/{ip}`——查询 IP 归属。`GET /api/logs`——最近日志。

规则热更新是最有价值的 API。你发现某个域名走代理不稳定——打开浏览器访问 API 端点，把它加到直连列表——保存——新规则立即生效。不需要重启程序，不需要断开已有连接。这就是"不停机运维"在家庭网络场景下的实践。

## 四

默认端口选了 8088，因为 8080 总被 Java 应用服务器和 Jenkins 占着。选端口就像选停车位——最方便的位置永远有人，你得学会往旁边走两步。
