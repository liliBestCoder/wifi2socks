# 第3篇：30 个模块的装配图 —— 别怕，我们一个一个拆

## 一、关于复杂系统的真相

我老婆前段时间买了一个宜家的衣柜，六大包板材，两百多颗螺丝，一本二十页的说明书。她花了一个周末装好了，中间哭了两次，最后多出来四颗螺丝。她问我这四颗螺丝是不是多余的，我说：在宜家的世界观里，没有多余的螺丝——只有你装错的地方。

复杂系统都是这样的。拆开来看，每一块板子都不难理解。但当你面对六大包板材和两百多颗螺丝的时候，你需要的不是立刻开始拧，而是先把说明书通读一遍，搞清楚 A 板为什么要连 B 板，抽屉的滑轨为什么要在装侧板之前固定。

这篇文章就是 wifi2socks 的说明书。

我会先给你一张"地铁线路图"——哪些模块在哪一层，数据是怎么从一条线换乘到另一条线的。然后我会把每个模块用一句话介绍清楚（不超过三十个字）。最后我们看看 `main()` 函数——这个不到 200 行的函数是整个系统的"启动仪式"，它的调用顺序不是随便排的。

读完这篇之后你不需要记住每一个细节。你只需要在脑子里留下一张图。后面每一篇文章会在这张图上找一个站，下车细逛。

这张图概括了数据平面的两条生命线：**直连路径**和**代理路径**。

直连路径：手机 → WiFi → NDIS → 包分拣 → NAT 查表 → 规则判断"直连" → 直接跟目标服务器通信 → 响应包注入回 NDIS → 手机收到。

代理路径：手机 → WiFi → NDIS → 包分拣 → NAT 查表 → 规则判断"代理" → 通过 SOCKS5 连目标服务器 → 响应转发回 NDIS → 手机收到。

这两条路径经过的模块不完全相同，但共享了前段的拦截层和 NAT 层。这种设计让"分流"变得非常自然——在规则匹配这一步做决定，后面的路自动分岔。

除了数据平面，还有**控制平面**——不直接处理数据包，但决定了数据包怎么走：

```
┌────────────────┐   ┌──────────────┐   ┌─────────────┐
│  config.ini    │   │  HTTP API    │   │  Geo/GeoSite │
│  配置加载      │   │  :8080       │   │  数据文件    │
└──────┬─────────┘   └──────┬───────┘   └──────┬──────┘
       │                   │                   │
       ▼                   ▼                   ▼
┌──────────────────────────────────────────────────────┐
│               RuleManager (规则引擎)                  │
│         Direct / Proxy / Block  三色灯               │
└──────────────────────┬───────────────────────────────┘
                       │
                       ▼
              ┌────────────────┐
              │   数据平面      │
              │  (上面的那张图) │
              └────────────────┘
```

现在你有一个大致的感觉了。接下来我把每个模块一句话说清楚。

## 三、25 个模块的一句话档案

**内核态（1 个）**

1. **WinPkFilter Driver**（`Common.h`, `ndisapi.h`）——在网卡和协议栈之间拦截所有以太网帧的 NDIS 驱动。系统的基石。

**驱动适配层（2 个）**

2. **WinPkFilterDriver**（`winpkfilter_driver.h/.cpp`）——对 WinPkFilter 的用户态封装。负责绑卡、读包、发包、管理 Worker Queue。整个系统最核心的类，代码也最长。

3. **PacketPool**（`packet_pool.h/.cpp`）——预分配 32768 个 `INTERMEDIATE_BUFFER` 的对象池。避免运行时 `new`/`delete` 的抖动和碎片。

**网络适配器管理（2 个）**

4. **WiFiAPManager**（`wifi_ap.h/.cpp`）——通过 WinRT WiFi Direct API 创建和管理 WiFi 热点。你手机搜到的那个 SSID 就是它广播的。

5. **Adapter**（`adapter.h/.cpp`）——管理有线网卡。自动发现以太网适配器、配置静态 IP、处理 WiFi/有线模式切换。

**基础协议服务（2 个）**

6. **DhcpServer**（`dhcp_server.h/.cpp`）——自建的 DHCP 服务器。给连上热点的设备分配 IP 地址，管理租约。

7. **NatManager**（`nat_manager.h/.cpp`）——NAT 映射表。记录"哪个内网 IP 的哪个端口在跟外网的谁通信"，是透明代理的账本。

**代理核心（3 个）**

8. **ProxyTCP**（`proxy_tcp.h/.cpp`）——TCP 透明代理。拦截 TCP 连接、跟上游 SOCKS5 握手、双向转发数据。代码最复杂、状态最多、坑最深。

9. **UdpProxy**（`proxy_udp.h/.cpp`）——UDP 透明代理。处理无连接的 UDP 数据报，管理虚拟端口映射。

10. **AppListener**（`app_listener.h/.cpp`）——监听本地端口的 TCP/UDP 服务。接收来自代理模块的内部请求。

**DNS 系统（4 个）**

11. **DnsCache**（`dns_cache.h`）——DNS 结果缓存。同一个域名查过一次就不用再查了。

12. **DnsOverTcpProxy**（`dns_over_tcp_proxy.h/.cpp`）——DNS over TCP 代理。当 UDP DNS 被污染或响应超过 512 字节时走这条路。

13. **DnsProbeTracker**（`dns_probe_tracker.h`）——DNS 探针追踪。根据 DNS 查询的域名推断流量属于哪个厂商（Google、Apple、OPPO 等）。

**深度包检测（1 个）**

14. **TlsParser**（`tls_parser.h/.cpp`）——解析 TLS ClientHello 提取 SNI 域名，解析 HTTP 请求提取 Host 头。

**路由与分流（3 个）**

15. **RuleManager**（`rule_manager.h/.cpp`）——规则引擎。维护三套规则（直连/代理/阻断），匹配 IP 和域名。

16. **GeoChecker**（`geo_checker.h/.cpp`）——GeoIP + GeoSite 数据库。判断一个 IP 是哪个国家的、一个域名属于哪个类别。

17. **ConfigLoader**（`config_loader.h/.cpp`）——解析 `config.ini` 配置文件，加载所有可配置项。

**并发与调度（3 个）**

18. **WorkerPool / Worker**（`worker.h/.cpp`）——IOCP 异步 I/O 线程池。8 个线程共享一个 IOCP，处理所有 socket 的收发完成通知。

19. **MainDispatcher**（`main_dispatcher.h/.cpp`）——主线程任务队列。Worker 线程把需要"回主线程执行"的任务丢到这里。

20. **ConnectionPool**（`connection_pool.h/.cpp`）——上游连接池。复用已建立的 SOCKS5 连接，减少握手开销。

**监控与管理（4 个）**

21. **TrafficManager**（`traffic_manager.h/.cpp`）——流量统计。记录 TAP 收发和代理收发的字节数，每秒计算速率。

22. **SimpleHttpServer**（`http_server.h/.cpp`）——内嵌 HTTP 服务器。提供 REST API 供外部查询状态和修改配置。

23. **Logger**（`logger.h/.cpp`）——异步日志系统。支持四个级别（DEBUG/INFO/WARN/ERROR），后台线程落盘。

24. **WifiAPListener**（`wifi_ap_listener.h/.cpp`）——WiFi 事件监听器。设备连上/断开热点时触发回调。

**入口（1 个）**

25. **wifi2socks.cpp**——`main()` 函数。按正确顺序启动所有模块，然后进入事件循环。

## 四、main() 的启动仪式——顺序为什么不能乱

来看看项目真正的 `main()` 函数（我删掉了无关细节，保留了完整的启动顺序）：

```cpp
int main() {
    // 0. 基础准备
    WSAStartup(MAKEWORD(2, 2), &wsa);      // Winsock 初始化
    SetPriorityClass(..., ABOVE_NORMAL);    // 提高进程优先级
    RoInitializeWrapper initialize(...);    // WinRT 初始化

    // 1. 加载配置
    load_config("config.ini");              // 读取 config.ini
    ApMode ap_mode = resolve_ap_mode();     // WiFi 模式还是网线模式？

    // 2. 配置日志
    AsyncLogger::instance().init("wifi2socks.log");

    // 3. 启动 WiFi 热点（如果是 WiFi 模式）
    if (ap_mode == WifiAp) {
        WiFiAPManager::instance().Start();
    }

    // 4. 启动 DHCP 服务器
    //    (WiFi 模式下 ICS 会接管 DHCP，所以跳过)
    if (ap_mode != WifiAp) {
        dhcp_server.start();
    }

    // 5. 启动流量统计
    TrafficManager::instance().start();

    // 6. 初始化 GeoIP/GeoSite
    GeoChecker::instance().init();

    // 7. 初始化数据包对象池 (32768 个)
    PacketPool::instance().init(32768);

    // 8. 找到要绑定的网卡
    string adapter_name;
    if (ap_mode == WifiAp)
        adapter_name = find_best_wifi_direct_adapter();
    else
        adapter_name = get_ethernet_adapters(...);

    // 9. 启动 IOCP 工作线程池 (8 个线程)
    WorkerPool::instance().init(8);

    // 10. 初始化 UDP 代理
    UdpProxy::initialize();

    // 11. 启动 WinPkFilter 驱动——开始截包！
    WinPkFilterDriver::instance().start_batch(adapter_name, ...);

    // 12. 启动 HTTP API 服务器
    SimpleHttpServer::instance().start(g_config.http_api_port);

    // 13. 进入主循环
    while (true) {
        MainDispatcher::instance().process_pending();
        // 每 1 秒：WiFi 保活、TCP 超时检查、NAT 清理
        // 每 5 秒：网络健康日志
        // 每 30 秒：P2P keep-alive
        WaitForSingleObject(..., 100);
    }
}
```

这个启动顺序是有讲究的，不能随便调换。为什么？

**配置必须在一切之前加载**，因为后面的所有模块都需要配置参数。

**WiFi 热点要在 DHCP 之前启动**，因为 WiFi 模式下 Windows 的 ICS 会自动接管 DHCP，我们自己的 DHCP 就不能启了。这个判断逻辑（`skip_dhcp`）必须在 WiFi 启动之后决定。

**GeoChecker 要在 WinPkFilter 之前初始化**，因为一旦驱动开始截包，包就会涌进来，这时规则引擎必须已经准备好 GeoIP 数据，否则每个包都要等文件加载——那酸爽。

**PacketPool 要在 WinPkFilter 之前分配**，因为驱动的 reader loop 一旦启动就会疯狂申请 PacketPool 里的 buffer。池子还没建好就开始游泳，你知道会怎样。

**WinPkFilter 必须最后启动**，因为它一旦启动，数据包就开始以每秒几千甚至几万个的速度涌入。前面所有的基础设施——NAT 表、规则引擎、Worker 线程池、UDP 代理——都必须已经准备就绪。这不是"优雅启动"，是"生存必需"。

主循环里的三个定时器也值得一说：

- **每秒**：检查 WiFi 热点是否还活着（`CheckKeepAlive`）、检查 TCP 代理有没有僵尸连接（`check_all_timeouts`）、清理过期的 NAT 映射（`cleanup`）。
- **每五秒**：打印网络健康日志（内存占用、网关邻居表活跃度）、打印 TCP/UDP 代理的全局统计。
- **每三十秒**：向所有 DHCP 客户端发一个 UDP 包（端口 9，discard 协议）——纯粹是为了防止 Windows 的 WiFi Direct 因为"没活动"而自动关闭热点。这个 trick 是一个凌晨三点调试出来的产物。

## 五、看完了图，然后呢？

你现在有了一张地铁线路图，和 25 个站点的名字。接下来的二十几篇文章，我们会在每一站下车，走到站台下面看铁轨是怎么铺的、信号灯是怎么接的、调度系统是怎么运转的。

下一站：NDIS。

NDIS 是整个 Windows 网络栈的地下室。我们会在那里看到数据包从网线到内存的完整旅程，以及 WinPkFilter 是怎么在这个地下室里安了一个"检查站"的。

如果你觉得"NDIS"这个词听起来很陌生——没关系。我第一次看到它的时候也是这么想的。但我保证，等你读完下一篇，你会觉得它不过就是 Windows 版的 netfilter。只不过微软的命名品味确实不如 Linux 那帮人。
