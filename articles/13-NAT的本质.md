# 第13篇：NAT 的本质 —— 网络世界的公司前台

## 一

如果你把 TCP/IP 比作邮政系统，那 NAT 就是公司前台。外面的人只知道公司的总机地址——"北京市朝阳区建国路 88 号"。你坐在三楼的某个工位上，外面寄给你的信，信封上写的是公司地址。前台小姐收到信，看一眼寄件人，查一下记录本："顺丰单号 12345？哦，是张三的信。张三，三楼十二排四号。"她转交给你。你回信，前台贴上公司的统一地址发出去。

NAT 的记录本上，每一行就是一个映射：谁（内网 IP:Port）在跟外面的谁（目标 IP:Port）说话。

## 二

NAT 要解决的核心问题：多台设备共享一个公网 IP 时，回来的包怎么区分？

三台手机（192.168.137.101, 102, 103）同时访问 `google.com:443`。三台手机发出的 SYN 包的源 IP 各不相同。经过软路由后，发到公网的包源 IP 被替换成软路由的公网 IP。Google 看到的三个连接来自同一个 IP 地址。

Google 的响应回来后——三个 SYN-ACK，目标 IP 都是软路由的公网 IP——路由器怎么知道每个包应该转发给哪台手机？

答案是：**端口映射**。软路由在每台手机发起连接时分配了一个本地端口：

```
101:45678 → Google:443  → 本地端口 50001
102:45678 → Google:443  → 本地端口 50002
103:52341 → Google:443  → 本地端口 50003
```

回来的包看目标端口：50001 → 转发给 101，50002 → 102，50003 → 103。这个映射表就是 NAT 的"流水账"。

## 三

NAT 有好几种类型。最常见的是 Full Cone NAT 和 Symmetric NAT。Full Cone 的意思是：映射建好之后，任何外部主机都能通过这个映射向内网发包——就像你给了一个对外地址，任何人都能寄信来。Symmetric 的意思是：内网 IP:Port 对外网主机的映射是一对一的——你访问服务器 A 映射到端口 50001，访问服务器 B 映射到端口 50002，即使内网源 IP 和端口相同。

Symmetric NAT 更安全但更不友好。两台都在 Symmetric NAT 后面的设备几乎不可能直接建立 P2P 连接——因为没有一方能猜到对方分配了什么端口。这就是为什么有些游戏联机需要"NAT 类型检查"——Open NAT（Full Cone）能联，Moderate NAT 可能联，Strict NAT（Symmetric）基本别想联。

我们的 NAT 目前是 Symmetric——安全的默认选择。改成 Full Cone 需要端口管理的重新设计，是一个高优先级的待办项。

## 四

在代码里，TCP NAT 查表的键是 IP + 端口的组合——一个 64 位整数：IP 左移 16 位，低 16 位填端口号。这个 key 在 `unordered_map` 里做哈希索引。UDP NAT 更复杂——需要整个四元组（src_ip + src_port + dst_ip + dst_port）做键，因为 UDP 没有连接概念，同一对客户端 IP:Port 可以向不同目标发数据报。

NAT 表的访问模式是"读极多写极少"。每个包都要查表，但只有新连接才需要写。所以用读写锁（`shared_mutex`）保护——读操作可以并发，不用互相等。在高吞吐量下，这比纯互斥锁快 3-5 倍。

清理机制是简单的定时遍历：每次主循环迭代时检查所有映射，超过超时时间（TCP 5 分钟，UDP 3 分钟）的条目直接删除。时间单位用的是 `GetTickCount64()`——系统启动毫秒数，不随系统时间调整而跳变。

## 五

NAT 的映射就像旅馆入住登记。客人来了（SYN），前台登记（创建映射）。客人在住期间（数据传输），每次进出大门（包转发）更新"最后活动时间"。客人退房（FIN/RST），前台过一段时间清理登记（超时清理）。如果客人偷偷溜了（连接异常断开），前台等退房时间到了自动收房（超时机制兜底）。
