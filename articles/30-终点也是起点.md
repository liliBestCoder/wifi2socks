# 第30篇：终点也是起点 —— 从软路由到家庭网络中枢

## 一

30 篇文章。从 NDIS 驱动的第一行 `#include` 到 HTTP API 的最后一个 JSON。现在回头看第一篇里的那句"我不是缺一个软路由用，我是不信邪"——这句话写在三千个小时之前。那时候刚装好 Visual Studio，WinPkFilter 的文档还没读完。现在项目跑在好几台机器上，每天处理几十个 GB 的流量，安安静静。

写代码有点像爬山。埋头爬了几个小时，回头看，山脚已经很远了。这篇文章是最后一次回头看。

## 二

我们做了什么？一个简短的回放。

在 NDIS 层拦截了所有数据包——在网卡驱动和协议栈之间，ICS 的二层转发之下。用 WiFi Direct API 创建了热点——然后跟 WinRT 的异步模型斗争了很久。写了一个 DHCP 服务器——从协议解析到 IP 池到租约管理，学会了在 NDIS 层直接构造以太网帧。建立了 NAT 连接追踪——TCP 的五元组映射，UDP 的虚拟端口管理。设计了规则引擎——用户显式规则优先，剩下交给 GeoIP 二分查找和 GeoSite 域名分类。实现了透明代理——NDIS 层拦截 → 重定向到本地端口 → NAT 缓存查真实目标 → 新建 TCP 连接 → 两条连接之间做数据桥接。TCP 的所有复杂状态管理由操作系统免费提供。做了 DNS 缓存、分流、反污染、DNS Probe 流量分类。深度包检测——TLS SNI 解析和 HTTP Host 嗅探。性能优化——IOCP 异步 I/O、无锁环形队列、False Sharing 消除、PacketPool 对象池、三级压力降载。最后装了 HTTP API 这个方向盘。

## 三

几个数字：内存 50-80MB，CPU 空闲 <1%、有流量 2-5%、跑满带宽 8-12%。延迟增加：直连 <1ms，代理 10-50ms（取决于 SOCKS5 代理）。这些数字说明一件事：现代 PC 做软路由绰绰有余。你的电脑在 99% 的时间里 CPU 是空闲的——让它顺便当个路由器，不会影响你打游戏。

## 四

还差什么？IPv6 完整支持（目前看到就丢），UDP Full Cone NAT（对 P2P 游戏更友好），多 WAN 负载均衡，Web 管理界面，插件系统让用户写 Lua 定制路由。Linux 移植——核心逻辑是平台无关的 C++，NDIS 部分换成 netfilter/TPROXY。这些是未来。

## 五

一台 24×7 开机的 PC，插着网线，连着所有设备。它可以不止是路由器——同时是 NAS（加几块硬盘跑 Samba）、Pi-hole（DNS 层广告过滤，你的 DNS 代理已经有了拦截域名的基础设施）、HomeAssistant（智能家居中枢，它已经管理着所有联网设备）、媒体服务器（Plex/Jellyfin）、VPN 网关（WireGuard 的 Windows 实现已经很成熟）。一台 PC 替代一堆设备。

## 六

最后一句。我写这个系列的初衷很简单：网络编程被过度神秘化了。"驱动开发"听起来像需要博士学位才能碰的事情，"透明代理"听起来像 CIA 的技术，"NAT"听起来像思科认证教材里的黑话。但当你真的打开这些黑盒子，你会发现——NDIS 驱动不过是用 IOCTL 读写数据，透明代理不过是把数据包重定向到本地端口然后桥接两个 TCP 连接，NAT 不过是一个记录了"谁是谁"的哈希表。

技术神坛上的每一个神，走近了看都是跟你我差不多的工程师——他们只是比你早开始折腾了几年。希望读完这个系列，你不会觉得写一个软路由有多难。它只是长，不难。
