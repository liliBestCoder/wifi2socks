# 第16篇：GeoIP —— 一个 IP 的地理归属怎么查

## 一

互联网在 1969 年诞生的时候，没人想过"这个 IP 是哪个国家的"会成为一个需要回答的问题。IP 地址只是一串数字，不携带地理信息。但现实世界有国界、有防火墙、有版权区域限制、有"该内容在您所在的地区不可用"。

于是有人开始把 IP 段和国家对应起来。最早做这件事的是 MaxMind。后来 V2Ray 社区基于类似的思路做了自己的 geoip.dat——专门针对中国用户的场景优化，比如"CN"标记更精准、IP 段覆盖更完整。

## 二

V2Ray 的 geoip.dat 是 Protobuf 编码的二进制文件。解析后得到一个按 start_ip 排序的 IP 段数组——大约 30 万条。每条记录包括 start_ip（起始）、end_ip（结束）、code_index（国别代码在字符串数组里的索引）。

30 万条 x 12 字节 = 3.6MB，加上索引和字符串约 5MB。对于现代计算机来说，5MB 常驻内存完全不是问题。

查询用 `std::lower_bound`——二分查找 O(log₂N)。30 万条最多 19 次比较就定位。但不用每次都二分——同一个 IP 被重复访问的概率极高。一个 TCP 连接有几十到几千个包，每个包都要查 GeoIP。第一个包 miss，后面的全部从缓存命中。所以加了一个 `unordered_map<uint32_t, bool> m_ip_cn_cache`，把二分查找的次数降低到了不到 1% 的包。

缓存的是"是不是中国 IP"这个布尔值——因为这是最常用的查询。如果将来需要更细的分类（"是不是俄罗斯 IP？"），缓存键要重新设计。

## 三

GeoIP 有一个不能忘的特殊情况：**私有 IP。** `10.x.x.x`、`172.16-31.x.x`、`192.168.x.x`、`127.x.x.x`——这些在 geoip.dat 里不存在，因为它们不属于任何国家。代码里有一个单独的 `is_private_ip()` 检查。如果忘了这个检查，私有 IP 会被二分查找判定为"不是中国 IP"→ 走代理。而局域网流量走代理是纯粹的浪费——这是规则引擎里私有 IP 被直接标记为 DIRECT 的原因。

## 四

除了"是不是中国"，还有额外的标记：比如"是不是腾讯 IP"。腾讯的游戏服务器（王者荣耀、和平精英等）IP 段单独被标记了 `FLAG_TENCENT`。这个需求不是预先设计的——是某天打王者荣耀延迟 200ms，查了一下发现游戏包走了代理。第二天就写了这个标记逻辑。

先有需求后有实现，是软件工程最真实的常态。架构师画的那张完美的 UML 图，永远是在代码跑了半年之后才画出来的。
