# 第10篇：网线模式 —— 低调的以太网适配器接管术

## 一

WiFi 是浪漫的，网线是可靠的。在一段长期关系中，可靠性比浪漫重要得多。

我打竞技游戏永远插网线。不是因为网线快——实际上现代 WiFi 6 的延迟已经压到 2ms 以下——而是因为网线不会在你开团的时候突然断连。WiFi 的信道干扰、隔壁的微波炉、你妈在楼下开吸尘器、甚至天气湿度——这些不可控因素在有线世界里全都不存在。

软路由也是同样的道理。如果它要 24×7 运行，在有线模式下跑比 WiFi 模式靠谱一个数量级。而且有线模式完全避开 WinRT 的所有坑——不需要跟 `WiFiDirectAdvertisementPublisher` 搏斗，不需要管 KeepAlive，不需要担心热点突然关闭。

## 二

Windows 用 LUID（Locally Unique Identifier）来标识网络适配器。这是一个 64 位数字，比 GUID 短，但功能类似。有 LUID，你就能调用 `AddIPAddress()`、配置子网掩码、设置跃点数。

我们的 `adapter.cpp` 里有一个 `get_ethernet_adapters()` 函数，枚举系统上所有适配器然后按标准筛选：必须是物理以太网（`IF_TYPE_ETHERNET_CSMACD`）、操作状态必须是 Up（网线插着）、可以按配置中的 hint 匹配描述或友好名称。

多数电脑只有一个物理以太网口，筛选结果通常是一个。如果有多个（比如装了 PCIe 网卡），取第一个。想用特定的那个？在 `config.ini` 里设 `wired_adapter_hint = "Intel"`。

## 三

给网卡配静态 IP 不能用 `AddIPAddress` 一调了事，因为 Windows 的 IP 配置是累加的——每次调用新增一个 IP，不会替换。如果重复运行程序，网卡上会堆叠多个相同的 IP，路由表直接混乱。

所以 `ensure_adapter_ipv4()` 的逻辑是：先检查是否已经有这个 IP → 有就直接返回 → 没有才调用 `AddIPAddress()` → 如果有别的 IP 占着位置（比如之前运行残留的），先删再加。

WiFi Direct 适配器的 IP 不能被手动修改——它由 ICS 自动管理。你在有线模式下需要自己配 IP，在 WiFi 模式下完全不能碰 IP。这两个模式在代码里是清晰两路分支，但一旦适配器名字确定了、IP 配好了，后续所有上层逻辑（NAT、规则引擎、透明代理）完全一样——它们不知道也不关心下面跑的是 WiFi 还是网线。

## 四

这就是分层的价值。WiFi 和网线的区别被隔离在适配器管理层，上层看到的只是"一个 NDIS 句柄 + 一个网关 IP"。将来如果要支持多 WAN（比如同时用 WiFi 和网线做负载均衡），底层的适配器管理要改，但上层一行不用动——只要所有上层都用"网关 IP"这个抽象，它们不需要知道物理层在发生什么。
